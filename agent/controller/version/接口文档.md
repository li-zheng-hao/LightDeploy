# Agent Version 接口文档

## 接口概览

本文档描述了Agent版本管理相关的接口，包括获取版本信息和更新Agent程序等功能。

## 1. 获取版本信息

### 接口信息
- **URL**: `GET /api/version`
- **功能**: 获取当前Agent程序的版本号
- **Content-Type**: `application/json`

### 请求参数
无

### 响应
```json
{
  "version": "1.1.1"
}
```

### 响应字段说明

| 字段名 | 类型 | 说明 |
|--------|------|------|
| version | string | 当前Agent版本号 |

## 2. 更新Agent

### 接口信息
- **URL**: `POST /api/version/update`
- **功能**: 更新Agent程序，支持热更新和自动重启
- **Content-Type**: `multipart/form-data`

### 请求参数

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| file | file | 是 | 新的Agent程序文件（.exe） |
| agentServiceName | string | 是 | Agent服务名称 |

### 响应
```json
{
  "message": "更新程序已启动，服务将在几秒后重启"
}
```

### 响应字段说明

| 字段名 | 类型 | 说明 |
|--------|------|------|
| message | string | 更新状态描述信息 |

## 更新流程详解

### 1. 文件处理
- 接收上传的新版本程序文件
- 将文件保存到临时目录（`temp/agent_new.exe`）
- 验证文件完整性

### 2. 更新脚本生成
自动生成批处理脚本（`update.bat`），包含以下步骤：
```batch
@echo off
net stop {服务名称}          # 停止当前服务
timeout /t 2 /nobreak       # 等待2秒
copy /y "{新文件路径}" "{当前程序路径}"  # 复制新文件
net start {服务名称}         # 启动服务
del "{新文件路径}"           # 删除临时文件
del "%~f0"                  # 删除批处理文件自身
```

### 3. 更新执行
- 创建新的进程组执行更新脚本
- 释放子进程使其独立运行
- 延迟1秒后退出当前程序

### 4. 服务重启
- 更新脚本自动停止当前服务
- 替换程序文件
- 重新启动服务

## 技术特点

### 进程管理
- 使用 `CREATE_NEW_PROCESS_GROUP` 创建新进程组
- 通过 `cmd.Process.Release()` 释放子进程
- 支持独立运行的更新进程

### 文件操作
- 自动创建临时目录
- 安全的文件替换机制
- 自动清理临时文件

### 服务管理
- 自动停止和启动Windows服务
- 支持自定义服务名称
- 优雅的服务重启流程

## 使用示例

### 获取版本信息
```bash
curl -X GET http://localhost:8080/api/version
```

### 更新Agent
```bash
curl -X POST http://localhost:8080/api/version/update \
  -F "file=@agent_new.exe" \
  -F "agentServiceName=LightDeployAgent"
```

## 注意事项

1. **文件格式**: 更新文件必须是可执行的.exe文件
2. **服务名称**: 必须提供正确的Windows服务名称
3. **权限要求**: 需要管理员权限来停止和启动服务
4. **更新过程**: 更新过程中服务会短暂中断
5. **自动重启**: 更新完成后程序会自动重启
6. **临时文件**: 更新完成后会自动清理临时文件

## 错误处理

### 常见错误及解决方案

| 错误类型 | 错误信息 | 解决方案 |
|----------|----------|----------|
| 文件上传失败 | "请上传更新文件" | 检查文件是否正确上传 |
| 路径获取失败 | "获取程序路径失败" | 检查程序运行权限 |
| 文件保存失败 | "保存更新文件失败" | 检查磁盘空间和权限 |
| 脚本创建失败 | "创建更新脚本失败" | 检查临时目录权限 |
| 进程启动失败 | "启动更新脚本失败" | 检查系统进程限制 |

## 安全考虑

1. **文件验证**: 建议在客户端验证文件完整性
2. **权限控制**: 更新接口应限制访问权限
3. **日志记录**: 所有更新操作都会记录详细日志
4. **回滚机制**: 更新失败时服务会自动回滚到原版本

## 性能优化

1. **异步更新**: 更新过程异步执行，不阻塞主程序
2. **临时目录**: 使用临时目录避免文件冲突
3. **进程管理**: 独立的更新进程确保更新可靠性
4. **资源清理**: 自动清理临时文件和进程
