# Agent Deploy 接口文档

## 接口概览

本文档描述了Agent部署相关的所有接口，包括服务管理（Windows SCM / Linux systemd）、文件比较等功能。接口在 Windows 与 Linux 上保持一致，agent 根据所在操作系统自动选择实现。

## 1. 部署服务（Windows / Linux 通用）

### 接口信息
- **URL**: `POST /api/deploy/deploy-windows-service`
- **别名**: `POST /api/deploy/deploy-service`
- **功能**: 部署服务，包括文件解压、服务停止/启动等操作；agent 会根据所在操作系统自动使用 SCM（Windows）或 systemd（Linux）
- **Content-Type**: `multipart/form-data`

### 请求参数

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| serviceName | string | 是 | 服务名称 |
| servicePath | string | 是 | 服务安装路径（文件夹路径） |
| exePath | string | 否 | 程序完整执行路径，Linux 下用于解压后赋予可执行权限 |
| file | file | 是 | ZIP压缩包文件 |
| onlyCopyFile | bool | 否 | 是否仅复制文件，不重启服务 |

### 响应
- **成功**: HTTP 200，无响应体
- **失败**: HTTP 400/500，错误信息

## 2. 安装服务

### 接口信息
- **URL**: `POST /api/service/install-service`
- **功能**: 安装新的服务（Windows 生成系统服务，Linux 生成 systemd 单元文件）
- **Content-Type**: `multipart/form-data`

### 请求参数

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| serviceName | string | 是 | 服务名称 |
| file | file | 是 | 程序压缩包 |
| servicePath | string | 是 | 服务路径（文件夹路径） |
| exePath | string | 是 | 程序完整执行路径 |
| exeParams | string | 否 | 程序执行参数 |

### 响应
```json
{
  "message": "服务安装成功"
}
```

## 3. 启动服务

### 接口信息
- **URL**: `POST /api/deploy/start-service`
- **功能**: 启动指定的服务（Windows 使用 SCM，Linux 使用 `systemctl start`）

### 请求参数

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| serviceName | string | 是 | 服务名称（Query参数） |

### 响应
- **成功**: HTTP 200，无响应体
- **失败**: HTTP 400/500，错误信息

## 4. 停止服务

### 请求参数

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| serviceName | string | 是 | 服务名称（Query参数） |

### 响应
- **成功**: HTTP 200，无响应体

### 接口信息
- **URL**: `POST /api/service/delete-service`
- **功能**: 删除指定的服务（Windows 停止并删除系统服务，Linux 停止、禁用并删除 systemd 单元文件）

### 请求参数

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| serviceName | string | 是 | 服务名称（Query参数） |

### 响应
```json
{
  "message": "服务删除成功"
}
```

## 6. 获取服务状态

### 接口信息
- **URL**: `GET /api/service/get-windows-service-status`
- **别名**: `GET /api/service/get-service-status`
- **功能**: 获取指定服务的运行状态（Windows 使用 SCM，Linux 使用 `systemctl is-active`）

### 请求参数

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| serviceName | string | 是 | 服务名称（Query参数） |

### 响应
```json
{
  "serviceName": "服务名称",
  "status": "状态描述"
}
```

#### status 状态说明
- `已停止`
- `正在启动`
- `正在停止`
- `正在运行`

## 7. 文件比较

### 接口信息
- **URL**: `POST /api/deploy/compare-files`
- **功能**: 比较本地文件与远程文件的差异
- **Content-Type**: `application/json`

### 请求参数

```json
{
  "servicePath": "服务路径",
  "fileInfos": [
    {
      "fileRelativePath": "文件相对路径",
      "fileName": "文件名",
      "fileSize": 文件大小,
      "modifyTimeStamp": 修改时间戳
    }
  ]
}
```

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| servicePath | string | 是 | 服务路径 |
| fileInfos | array | 是 | 文件信息数组 |
| fileInfos[].fileRelativePath | string | 是 | 文件相对路径 |
| fileInfos[].fileName | string | 是 | 文件名 |
| fileInfos[].fileSize | int64 | 是 | 文件大小（字节） |
| fileInfos[].modifyTimeStamp | int64 | 是 | 文件修改时间戳 |

### 响应
```json
{
  "fileInfos": [
    {
      "fileRelativePath": "文件相对路径",
      "fileName": "文件名",
      "fileSize": 文件大小,
      "modifyTimeStamp": 修改时间戳
    }
  ]
}
```

## 错误响应格式

所有接口在发生错误时都会返回统一的错误响应格式：

```json
{
  "error": "错误描述信息"
}
```

## 注意事项

1. 文件上传接口需要使用 `multipart/form-data` 格式
2. 服务名称参数在所有相关接口中都是必填的
3. 文件比较功能会对比文件大小和修改时间，时间差异超过5秒认为文件不同
4. 部署服务时会自动处理服务的停止和启动
5. 所有接口都支持SSE消息推送，可以实时获取操作进度
